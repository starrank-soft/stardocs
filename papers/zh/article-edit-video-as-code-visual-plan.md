# 《Edit Video as Code》视觉与演示计划

> 目标：让每张图承担解释或证据功能，不用装饰性“AI 机器人”填充版面。

## 一、视觉节奏

长文采用“封面建立隐喻—架构图建立全局—局部图解释难点—动态演示形成体验”的节奏。原则上每经过一到两个核心概念，就出现一次不同形式的视觉信息，但连续代码示例之间不机械插图。

统一视觉语言：深蓝背景表示权威工程与运行态；青色表示 Agent、文件和读取路径；紫色表示 DSL 与协议；珊瑚色和琥珀色表示时间线、运动与人类判断。

## 三、动态演示

### D1：Agent 剪辑闭环

用户任务固定为：“找到产品演示镜头，把它缩短到三秒，并在后面增加一张产品海报。”画面左侧显示 `glob`、`head`、`grep`、`read`、`edit`，右侧显示同一条时间线从五秒片段变为三秒片段并插入海报。

- 原理 Demo：[`../../demos/edit-video-as-code/index.html`](../../demos/edit-video-as-code/index.html)，已完成；
- 产品录屏：待准备无敏感信息的 StarCut 示例工程；
- 建议成片：12–18 秒，无旁白也能看懂。

### D2：流式编辑

模型逐步输出 `PATCH` 和 `POST`。画面依次展示路径确定、操作头形成、完整操作闭合和领域验证；执行环境可以选择按完整操作渐进提交，也可以在整次调用结束后统一提交。演示重点是“流式解析与提交策略解耦”，不展开内部传输实现。

- 原理图：已完成；
- 产品录屏：待 Agent 流式调用界面稳定后录制；
- 建议成片：8–12 秒，适合循环播放。

### D3：剪早、剪准、剪晚

读者在同一段动作中选择三个剪点并反复播放。三个版本都满足结构约束，但运动兑现、连续感和能量释放不同。

- 交互 Demo：[`../../demos/edit-video-as-code/index.html`](../../demos/edit-video-as-code/index.html)，已完成；
- 真实素材版：待拍摄或生成一段版权清晰、动作相位明确的素材；
- 建议素材：接球、转身落座、拿起产品或推门，不使用依赖对白语义的片段。

### D4：人类接管

Agent 修改一个 Clip 后，人类立即在时间线上继续拖动、修改属性并 Undo。该演示用来证明“文件接口和 GUI 编辑的是同一工程”，比单独展示工具成功返回更有说服力。

- 产品录屏：待录制；
- 建议成片：10–15 秒；
- 必须保留 Timeline、属性面板和 Undo 反馈，不只展示最终画面。

## 四、发布格式

- 封面与氛围图保存 PNG 或 WebP；
- 架构图、流程图和协议图保留 SVG 源文件；
- 实机演示保留 MP4 原始文件，并提供静态海报；
- GitHub Markdown 使用海报链接到视频，正式站点再嵌入 `<video>`；
- 不把代码和界面录成低分辨率 GIF，避免文字不可读；
- 不制作没有真实实验数据支撑的性能柱状图或 token 节省比例图。
