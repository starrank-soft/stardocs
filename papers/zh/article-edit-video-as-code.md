# Edit Video as Code：将视频工程映射为 Coding Agent 可读写的虚拟文件视图

> 面向公众的技术文章
>
> 核心命题：不是让 AI 模拟人类点击剪辑软件，也不是让 AI 用代码重新生成一条视频，而是把已经建模的视频运行态，映射成一套 AI 可以像代码仓库一样发现、读取、定位、局部修改和验证的虚拟文件视图。

这是一次接口尝试。我们还不能回答「为什么 AI 会写代码、却还不太会剪视频」，也不能证明换一套机制之后效果一定更好。现在能写清楚的，只是我们改了哪一层、为什么这样改，以及它仍然没有回答什么。

Coding Agent 能在大型仓库里工作，并不只因为模型会生成代码。仓库提供了稳定路径、按需读取、局部补丁、编译与测试，以及人类可以审查并接手的 diff。视频编辑里常见的另外三条路——看截图点按钮、为每个动作准备细粒度工具、或让模型重写整份工程——都可以工作。我们尝试的是另一条：让已经建模的视频工程，复用 Coding Agent 已经熟悉的文件式工作方式。

## 这不是用代码生成视频

FFmpeg 脚本、Remotion 页面或 Blender 脚本都可以生成视频。它们通常建立的是一套新的渲染程序。生成结果未必还是一个能被普通剪辑界面继续编辑的工程。

Edit Video as Code 尝试做的是另一件事：

- AI 改的是用户当前打开的项目；
- 改完后，时间线、预览和属性面板看到同一结果；
- 用户可以继续拖动、调整和撤销；
- 人和 AI 不需要在两个工程之间导入、导出或同步。

所以，「像 Coding 一样剪辑」不是让模型输出一段 FFmpeg，也不是让所有剪辑师去写 XML。它只表示：把视频工程映射成一份可寻址、可局部修改、可验证、可由人接手的工作视图。

## 虚拟文件视图映射什么

模型不该在每一轮上下文里携带完整时间线。项目文件保留权威结构，Agent 根据任务先定位，再读取。

一个视频项目可以对 AI 呈现成这样：

```text
assets/
  product-demo.mp4
  product-shot.png
docs/
  script.md
compositions/
  main.vml
```

这棵树是给 AI 用的工作视图，不是把内部存储逐项摊开，也不是复制一份临时目录再做双向同步。文件负责发现和读取；真正写入仍然回到原来的项目状态，并经过领域约束：这条轨道能否放这种片段，素材是否存在，时间关系是否合法。

它需要两种地址。文件路径负责发现：产品演示在哪个素材里，哪条时间线引用了它。稳定节点 ID 负责修改：找到之后，改的是 `compositions/main.vml#clip_product`，而不是「左边数第三条轨道的第 12 个片段」。数组下标是序列化布局，不是语义身份；前面插入一条轨道，整条路径的含义就会变。

于是一次任务可以只动相关范围。用户说：找到产品演示镜头，把它缩短到三秒，并在后面加一张产品海报。Agent 不必先看完整时间线。它可以搜索素材引用，读目标附近的结构，然后只改这一处：

```text
grep("assets/product-demo.mp4", "compositions/*.vml")
→ compositions/main.vml#clip_product

PATCH #clip_product
把时长改为 3 秒

POST 同一轨道
在它后面插入产品海报
```

读取范围跟当前任务有关，不跟项目总大小绑定。修改范围跟用户意图有关，不要求复述整条时间线。时间线可以对 AI 呈现为可读文本，但权威状态不是这段文本，所以不能靠全文替换来改结构。

AI 看到的是文件，改的仍然是专业编辑器里的同一份工程。

## 人机共用同一份工程

如果 AI 维护一份「AI 时间线」，人类界面再维护另一份「真实时间线」，人要接管就得导入、导出、对差异。我们把两种入口接到同一份权威状态上：人拖动时间线，和 Agent 提交一次局部修改，进入的是同一个项目模型。预览、撤销、协同走原有通道。

人类仍然使用时间线、预览和拖拽，去做探索和审美判断。AI 使用文件式语义接口，去做定位、批量修改和可重复操作。AI 没有产出一个封闭的最终视频，而是在专业编辑工程中留下可见、可撤销、可继续修改的结构变化。

[SWE-agent](https://arxiv.org/abs/2405.15793) 说明：给语言模型的计算机接口，会影响它完成软件工程任务的能力。视频编辑把同一个接口问题带到了连续时间、媒体引用、视觉验收和协同状态里。我们借用的是这个问题，不是把软件工程工具直接搬进剪辑器，也还没有在视频任务上复现它的结论。

## 这仍然只是机制，不是答案

这套映射改变的是 Agent 看见和修改工程的方式。它没有回答模型为什么不擅长剪辑，也还没有证明它比 GUI Agent、多工具 Agent 或完整工程重写更成功。那些路线都可以有效。要比较的是：在真实后期制作任务里，步骤、上下文、错误恢复和人工接手成本会不会变化。这些评测仍在设计中。

视觉好不好看，类型系统也判不了。程序可以拒绝非法轨道、断裂引用和错误时长；构图、节奏和审美仍然要看画面，也仍然需要人。

局部编辑如何写成短协议、如何随模型输出逐步执行，是下一层的问题。更完整的研究设计、对比实验和待补证据，见 [Edit-as-Code 论文母稿](./03-edit-as-code.md)；编辑协议见 [REST-Edit](./02-rest-edit.md)。

## 结语

视频工程不会因为加上一层文件视图，就变成普通文本。它仍然包含连续时间、媒体引用、渲染状态和专业约束。

我们做的，是在专业运行态和 Coding Agent 之间加一层映射：项目可发现，状态可寻址，修改可局部化，错误可验证，人类可接管。这是一种可工作的接口形状。它是不是更好的剪辑方式，要等任务和对照实验来回答。
